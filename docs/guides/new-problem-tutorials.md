# 競賽與專題逐題教學

學習入口為 `/courses/practice`，每題教學為
`/courses/practice/lessons/<problemCode>`。依主題、難度、題號或題名搜尋，
並沿用既有的逐步動畫及 C++／Python 切換介面。
原有資料庫課程中的題目也會連到對應教學，不需要另外建立課程或寫入正式資料庫。

## 驗證

```sh
npm run test:new-problem-lessons
npm run test:new-problem-lessons -- --batch practice1 --runtime
npm run test:new-problem-course
```

第一項核對完整題號清單、來源範例、動畫索引與各題的獨立測試。
`--runtime` 編譯並執行真正呈現給學習者的 C++／Python 程式，
測試全部公開範例與 `scripts/fixtures/new-problem-lessons/*-checks.json` 的獨立案例。
Windows 上由 Node 呼叫既有 WSL `kali-linux`，C++ 程式僅在 Linux `/tmp` 編譯、執行；
不產生或執行 Windows 測試執行檔。
CI 以七個批次執行相同的 Linux 驗證。
使用 `boost::multiprecision::cpp_int` 的 C++ 解法需要 Boost 標頭；
CI 明確安裝 `libboost-dev`，評測主機的安裝步驟也已在 `sandbox-runner/README.md` 補上。
其餘 183 份原先未使用大整數的程式已移除多餘的 Boost 引入。
本次未修改正式評測機套件，也未驗證線上主機是否已具備這項依賴。
加上 `--report <path>` 可保存逐題結果與兩種程式的 SHA-256；CI 會保存這些報告。
若只修改個別題目，可用 `--codes b133,b233` 增量重驗。
`scripts/summarize-new-problem-verification.mjs` 接受各批及增量報告的檔案路徑，
逐題核對目前程式與測試案例的雜湊；修改前的證據不計入通過數，
每題都必須有匹配目前檔案的驗證紀錄才會通過。
若重新產生教學資料，可用 `node scripts/format-new-problem-lessons.mjs` 統一格式，
再執行程式驗證，確保測的是實際呈現給讀者的版本。

網頁測試只使用自行建立的拋棄式 SQLite 資料庫與本機伺服器，
核對 a／b 題號、題名搜尋、教學按鈕、公開權限、刪除題目及課程導覽。
正式資料庫不參與測試。CI 使用正式 build 的伺服器。

2026-11-03 最終本機紀錄：647 題每種語言各通過 1,122 組公開範例與
4,946 組獨立案例，共 12,136 次程式執行；合併七批及增量報告後，
全部目前程式與案例的雜湊相符。覆蓋核對為 1,411 組來源範例與
7 個標示清楚的自製教學例。正式建置、型別檢查、lint、保護式題面 migration
測試，以及新課程／既有課程版型／CPE／TOI 潛力組共 33 項網頁測試通過。
新增教學與既有 a344 的正確性及效能限制仍依下述說明保留。

測試通過代表列出的案例通過，不代表已證明所有隱藏測資或所有解法正確。
未釐清的題面矛盾不應以捏造解答、特判公開範例或通用占位教學掩蓋。
既有 a344 的規格待釐清標示保持適用。

對齊倉庫評測設定。未在正式評測機執行這些提交。
