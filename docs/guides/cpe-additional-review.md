### a675：空間文字漏算輸入（主審已修）

原先只有「空間 O(N₂)」，但 C++ 同時保存 `a(N₁)`、`b(N₂)`、`dp(N₂+1)`，內層另有一列。單組總空間為 O(N₁+N₂)，只有 DP 工作區為 O(N₂)。例如 N₁=100、N₂=1 時，內層共 105 個整數槽位。

Python 的 `iter(map(int, sys.stdin.buffer.read().split()))` 仍由迭代器持有整份切詞列表，不能省略其餘資料組的輸入緩衝。建議文字（本輪結尾已看到主審採用）：

> 每筆時間 O(N₁N₂)，DP 工作空間 O(N₂)；C++ 含兩塔輸入共 O(N₁+N₂)，Python 另有整份輸入切詞緩衝 O(T)，T 為全部輸入長度。

這是已確認、已由主審修正的註解缺陷，不是 LCS 答案錯誤，也不是本工作修改的教材。

### a685：避免負零的承諾沒有完整實現

位置：`src/lib/cpeLessons/batch4/part3.ts`，第二段 explanation，以及 C++ 的 `fabsl(x/y) < 0.0005L` 與 `setprecision(2)`。

```text
1
0 0 1 1000 -1 0 0 -1
```

兩線為 y=1000x 與 y=−x−1，交點恰為 (−1/1001,−1000/1001)。x 約 −0.000999，不通過 0.0005 門檻，保留兩位小數卻是 `-0.00`。依目前分支／格式，交點行為：

```text
POINT -0.00 -1.00
```

explanation 明確承諾「避免 −0.00」，因此這是可重現的教材文字／實作不一致。若保留承諾，修正候選為先格式化兩位小數，再把恰為 `-0.00` 的欄位改成 `0.00`，比在捨入邊界另猜 epsilon 清楚。Python 的相同門檻也值得主審處理，但本輪不宣稱已全面讀過其 Python。

[UVa 378 原始 PDF](https://onlinejudge.org/external/3/378.pdf) 允許本例座標、要求兩位小數，但未明文禁止負零。因此只列為確定的教材承諾失配，**不把它說成已證明的評測 WA**。本輪以精確分數及 Node 的兩位小數顯示交叉檢查，未執行原生 C++。

### a747：缺席查詢會插入簽章，空間與查表成本敘述不符

位置：`src/lib/cpeLessons/batch5/part2.ts`，complexity 及查詢內 `auto &a = dict[signature(s)]`。

```text
1

1
a
b
cc
ddd
END
```

字典只有 `a`，三個查無結果的查詢卻分別插入空向量，map 鍵數由 1 變成 4。一般化為 Q 個互不相同的缺席簽章，儲存會隨 Q 增加，不是原文只依 N、L 計算的 O(NL)。[UVa 630 原始 PDF](https://onlinejudge.org/external/6/630.pdf) 與快照都未限制查詢數，不能用 N<1000 代替 Q 的上限。反例的答案輸出仍然正確；缺陷在額外儲存與複雜度宣稱。

`std::map` 也不是雜湊表，原預處理與每查詢成本均漏算有序查表。若保持程式，空間上界須含 O((N+Q)L)，查表受持續增長的 map 影響。較好的修正候選是查詢改用 `find`，不新增缺席鍵，再分語言描述：

> 字長至多 L。C++ 的有序 map 每次查表最多 O(L log(N+2))；預處理 O(NL(log(L+1)+log(N+2)))，每查詢 O(L(log(L+1)+log(N+2))+輸出字元數)。不插入查詢鍵時儲存 O(NL)。Python 雜湊字典另註平均查表成本。

map 大小變化是依 C++ `operator[]` 必然插入的語意逐步分析，沒有冒充原生程式的實測結果。

### a794：未限硬幣數量時，總錢包 DP 過大且 int 會溢位

位置：`src/lib/cpeLessons/batch6/part1.ts` 的 `int w`、`w += v[i]*c[i]`、兩個 `vector<int>(w+1)`。重新查閱 [UVa 166 原始 PDF](https://onlinejudge.org/external/1/166.pdf)，和快照一樣只限制售價小於 5.00，未限制硬幣數量，不能把售價上限當錢包總值上限。

```text
0 0 0 0 0 60000000 2.00
0 0 0 0 0 0
```

應只付一枚 2 元，答案為寬度 3 的 `  1`。但縮放後 `40*60000000=2400000000`，超過 32 位有號 int，計算 w 即有未定義行為。這是原碼／數值界線證據，沒有宣稱未定義行為會固定產生某種輸出。

較小的 `0 0 0 0 0 10000000 2.00` 尚未 int 溢位，兩個 DP 陣列卻共有 800000002 個 int；在 4-byte int 平台，僅陣列就需 3200000008 bytes。未實際配置這筆資源，也不聲稱正式記憶體上限是多少。

保守修正方向供新審查者驗證：價格 p（5 分單位）≤99；任意逐枚付款至首次達到 p，最多付 p 枚，溢付最多 39 單位，以 1 單位幣找零最多 39 枚。因此存在總交換數≤p+39≤138 的解。最優解付出枚數也≤138，支付量不超過 `40*(p+39)≤5520`。可按此保守界線裁切 DP 與各面額有效數量，並在原始數量乘法前飽和。p=0 直接回答 0。不是只把 w 改成 64 位、仍配置整個錢包。

### a798：C++ 有序 map／set 的成本不是線性

`src/lib/cpeLessons/batch6/part2.ts` 宣稱每筆 O(V+E)，但讀邊用 map、走訪用 set 和 `g[x]`。語意判樹未找到反例，C++ 保守時間應為 O((V+E)log(V+1))，空間 O(V+E)。Python 雜湊容器可另標平均 O(V+E)。這是實作成本文字修正，不是樹判定錯解。
