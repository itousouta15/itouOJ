## 確認並修正的教材缺陷

- a006：原顯示 `8 3 11 → 11` 不是公開範例，改成第一組 `3 7 5 → 7`，同步修正全部動畫狀態。回歸測試獨立計算每個已處理前綴的最大值。
- a029：原顯示容量 5、答案 16 的自訂資料，改成公開的容量 10、三件 `(5,60)、(4,40)、(6,70)`、答案 110。動畫的四份 DP 陣列由獨立物品子集合枚舉核對。
- a007：原文暗示容量一律可乘 100 變成精確整數，題面沒有給這種一般輸入限制。改為明確說明這對固定資料成立，參考程式按公開範例讀四個值；不宣稱支援任意精度的小數。
- a019：區分比對所需的 O(1) 額外狀態與兩份輸入字串的儲存。
- a023、a449、a451、a452、a453、a454：原先只寫 O(1) 或 O(100) 空間，忽略 Python 整批切詞或輸入陣列；改列 C++ 串流與 Python 總空間。
- a030：題面允許重邊。惰性堆積可有 O(M) 筆紀錄，不能用簡單圖的邊數限制直接將 log M 換成 log N；改為 O(N+M log(M+2))，加上 50000 條遞減權重重邊的壓力資料。
- a433：Python 除了 N 個所選值，還保留目前一列 M 個值；改為 O(N+M)，C++ 仍為 O(N)。
- a447：兩種程式都保存 m 個長度 n 的遮罩，總空間應為 O(mn)；O(n) 只適用於單層還原的額外工作空間。
- a455：從左側交錯分組，在偶數長度時只是交換 A、B，取絕對值仍相同，不能稱其答案錯誤。修正陷阱說明；第二個動畫步驟也不再聲稱已讀取留待第三步的最左字元 2。

## 規格疑點與驗證界限

- a007 沒有一般輸入格式或容量／價格範圍，只有固定敘述與一組輸入範例。只確認已定義的固定比較；不替未知隱藏測資補規格。
- a023 的 F 寫「60 分以下」而 D 明列 60–69；公開範例將 60 分歸 D。教材依明確的 D 區間與範例處理，沒有改題面。
- a026 的 N=1 沒有存在的鄰居。程式按「嚴格高於所有存在的鄰居」解讀為 1，但題面沒有單獨說明；本次硬性邊界測試使用明確的四格平台，不以單格解讀作評測證據。整數數值上限也未列出，C++ `int` 的範圍不能由此得到全面保證。
- a375 孤立正值起點無法完成「持續右轉直到可進入」，既有防無窮迴圈保護不是題目新增的合法答案。寶石上限未列出；C++ 既有 64 位元假設與 O(G) 模擬仍有限制。沒有把未定義情形加入有權威答案的測試。
- a417 未列流量上界，a424 未列係數上界；有限資料及 64 位元 C++ 程式不能證明任意大整數皆安全。a445 的操作數上限也未明列。這些屬數值／資源範圍未完整定義，沒有自行修改題目或評測資料。
- a423 全圖為 -1 時沒有城市極值，既有輸出 0、0 為防禦約定；a441 所有候選都出現時沒有定義輸出。測試不為這兩種情況發明標準答案。

- a367、a372 等組合搜尋的完整最壞資料效能尚未逐一量測。最大深鏈、超長數字與重邊壓力資料只驗證指定情境，不涵蓋所有時間與記憶體最壞情況。

## 驗證工具與執行方式

新增工具為 `scripts/lib/check-apcs-tutorial-audit.mjs` 與同名 `.py`。Node 使用既有 TypeScript 載入器，Python 執行教材內的原始程式。每題都有公開範例與一個明列理由的邊界／規則例，較高風險者另有固定種子 20261020 的小規模枚舉。a007 的規則例仍是固定題面資料，不代表額外數值範圍的驗證。

預設入門黃金範例來自父工作加入的 `apcsIntroProblemCatalog`，歷屆來自 `apcsPastExamSamples`，不回退到教材自己的輸入輸出。`--source` 可改用新擷取的完整快照，會要求每個選定題號存在，並確認教材顯示的輸入與輸出同時匹配一組公開範例。

```text
node --import ./scripts/ctf-test-loader.mjs scripts/lib/check-apcs-tutorial-audit.mjs --python /path/to/python3 --stress

node --import ./scripts/ctf-test-loader.mjs scripts/lib/check-apcs-tutorial-audit.mjs --python /path/to/python3 --cxx /path/to/g++ --stress

node --import ./scripts/ctf-test-loader.mjs scripts/lib/check-apcs-tutorial-audit.mjs --python /path/to/python3 --cxx /path/to/clang++ --compile-only --stress --source ../tutorial-audit-source/all-problems.json --temp-root /writable/temp
```

`--python` 必填；不給 `--cxx` 就只執行 Python。給 `--cxx` 會逐題編譯及執行 C++，`--compile-only` 則只編譯 C++，仍執行 Python，且必須搭配 `--cxx`。`--code a006,a029` 可限縮題號；`--stress` 加入五組較大資料；`--temp-root` 指定編譯暫存資料夾。完整選取 113 題時，沒有 `--stress` 為 908 組，啟用時為 913 組；公開範例共 226 組。測試數包含重複驗證同一固定規則，不宣稱全部輸入都相異。

本機 Python：113 題、226 組公開範例，加上規則、枚舉及壓力資料合計 913 組通過。既有 `verify-apcs-lessons.mjs --python ...` 亦通過 104 題／212 組歷屆公開範例。

另在獨立 Node 子程序記憶體內分別放回 a006、a029 的舊輸入與舊答案，預設驗證均以 `displayed sample differs from source` 拒絕；沒有寫回檔案。這確認公開黃金範例來源可抓出原本的範例錯配，並非循環相信教材自身資料。修改的三份 TypeScript 與新增 JavaScript 通過定向 ESLint，追蹤中的修改通過 `git diff --check`。

本機 C++：113 題全部以 clang++、C++17、O2 編譯成功；執行模式在 a006、a007 各組通過後，被 Windows 應用程式控制的 WinError 4551 阻止後續新執行檔啟動。這是本機執行環境限制，不能報成其餘 C++ 已執行通過。提供完整執行介面供父工作在 CI 執行；沒有停用或繞過作業系統政策。
