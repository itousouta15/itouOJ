# App 實作搜尋與六格導覽設計

## 目標與範圍

Capacitor App 不顯示網站頂部 Header，因此把實作題搜尋移到 `/problems` 頁面，讓使用者進入「實作」後可立即找題。App 的底部導覽固定六格，保留高頻的解題與成就入口，低頻個人與管理功能集中在「更多」。

本次只改 App 專屬介面與既有搜尋元件的呈現方式；網站版 Header 搜尋、題目搜尋 API、題目列表的伺服器端篩選與網址格式均維持既有行為。

## App 實作頁搜尋

`/problems` 在 App（`html[data-app]`）中，於「實作」標題下、標籤篩選列前顯示一個完整且固定展開的搜尋框。它沿用既有即時建議行為：

- 輸入文字後呼叫既有 `/api/search/suggest`，可同時列出符合的實作題與標籤。
- 點選題目後導向該題；點選標籤後加入搜尋 token，並以 token 的交集繼續搜尋。
- 鍵盤上下鍵可移動建議項目，Enter 選取目前項目，Escape 收起建議清單但保留已輸入文字與 token。
- 建議清單以浮層覆蓋題目列表，不改變題目列表或標籤列的位置；空結果與載入中沿用既有提示。
- 在網頁版，頁內搜尋元件不顯示，現有 Header 搜尋保持其收合／展開行為與樣式不變。

元件需增加明確的頁內呈現模式，而不是複製搜尋狀態或 API 邏輯。頁內模式永遠可輸入；Header 模式維持目前的收合按鈕。兩種模式共用搜尋、建議、鍵盤與導向邏輯。

## 六格底部導覽

App 底部列固定顯示以下順序，避免登入狀態或管理員身分改變列上的格數：

1. 首頁（`/`）
2. 實作（`/problems`）
3. 識讀（`/recognition`）
4. 紀錄（`/submissions`）
5. 排行（`/ranking`）
6. 更多（不直接換頁）

「更多」開啟 App 內的底部選單，內含：

- 已登入：訊息、我的帳號；若為管理員，再列出管理入口。
- 未登入：登入入口。
- 訊息未讀數從原本的訊息分頁移到「更多」圖示上，未讀數超過 99 顯示 `99+`。

底部選單以 `dialog` 語意與可見標題實作，開啟時將焦點移到選單；可按背景、Escape、關閉按鈕或任一選項關閉。從更多選單前往的頁面（訊息、帳號、管理）時，「更多」保持選取狀態。底部列的每一格仍維持至少 44px 高的觸控範圍；六格在窄螢幕平均分配寬度，文字維持單行、不橫向捲動。

「更多」的三點圖示只作為次要入口提示：在 App 中以 14px 的緊湊水平省略號呈現，微調字距與垂直位置；其他五個主導覽圖示維持 20px。未讀徽章的位置與顯示規則不變。

## 架構與資料流

- `HeaderSearch` 擴充為 Header 與 App 頁內兩種顯示模式，共用單一組搜尋狀態、延遲請求、建議清單與鍵盤操作。
- 題目列表頁只負責放置 App 頁內模式；透過 `html[data-app]` CSS 使其不影響網頁版伺服器渲染。
- `BottomNavLinks` 保留路由判斷與登入／管理員資料輸入，改為固定六個主項目，並管理「更多」底部選單的開關、焦點與關閉行為。
- 現有 `BottomNav`、`getNavInfo` 與未讀數查詢不新增資料庫查詢；未讀數只換到更多圖示顯示。

## 錯誤、可及性與相容性

- 搜尋 API 失敗時，使用現有空結果狀態，不讓輸入框失焦或阻礙題目列表瀏覽。
- App 專屬樣式一律加在 `html[data-app]` 範圍下；一般瀏覽器和桌面版不會出現 App 頁內搜尋或底部導覽。
- 所有新按鈕明確設為 `type="button"`，避免誤送出表單。
- 更多選單包含 `aria-expanded`、`aria-controls` 與可辨識的關閉控制；點擊／鍵盤操作均可完成相同行為。

## 驗證

- 執行 TypeScript 檢查、lint 與 production build。
- 手動檢查 App WebView：搜尋框始終可輸入、建議可用鍵盤與觸控選取、選擇標籤後 token 正確顯示。
- 手動檢查六格導覽的所有路由、更多選單的登入／管理員差異、未讀徽章轉移以及 Escape／背景關閉。
- 以一般瀏覽器檢查 Header 搜尋仍收合呈現，且 `/problems` 不會多出 App 專屬搜尋框。
