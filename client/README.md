# itouOJ 收件程式

斷網比賽用的 Windows 桌面程式。比賽期間選手機沒有網路，這支程式只把程式碼存在
**本機**；等重新連網後一次上傳到伺服器，由 judge 補判，結果照常出現在網站上
各自的帳號與計分板。

## 為什麼是 23 KB

用 Windows 內建的 .NET Framework 編譯器建置，只依賴 .NET Framework 4.x
（Windows 10 / 11 都內建）。**選手機不需要安裝任何東西**，複製 exe 過去就能跑。

## 建置

```powershell
.\client\build.ps1
```

需要 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`，這是 Windows
內建的，不用裝 Visual Studio 或 .NET SDK。產出 `client\itouOJ-Submit.exe`。

## 畫面

三個分頁：

| 分頁 | 給誰用 | 內容 |
|---|---|---|
| **作答** | 選手，比賽中 | 左側題目欄（每題顯示「已交 n」/「草稿」徽章）+ 右側選題目、開啟題目 PDF、寫程式碼、測試執行、提交 |
| **收件紀錄** | 選手，賽後 | 已收件清單、上傳到伺服器 |
| **賽前設定** | 監考 / 選手，賽前 | 帳號登入 / 登出（永遠可用）、選比賽、管理員設定（可上 PIN 鎖） |

版面用 TableLayoutPanel / FlowLayoutPanel 組成，視窗大小與螢幕解析度
（含 125% / 150% 縮放）改變時只有編輯區會伸縮，其餘區塊位置不變。

## 使用流程

### 1. 賽前設定（需要網路）

在每一台選手機上，切到「賽前設定」分頁：

1. 執行 `itouOJ-Submit.exe`
2. 填伺服器網址（例如 `https://oj.itousouta.me`）
3. 按「用瀏覽器登入」，在瀏覽器裡用平常的方式登入（帳號密碼、Google、Discord
   都可以），瀏覽器會自動把授權跳回程式
4. 從下拉選單選擇比賽

### 1b. 管理員設定（題目 PDF 位置）

「賽前設定」分頁 →「題目路徑與編譯器設定」：

- **題目 PDF 資料夾**：檔名用題目代號（`A.pdf`、`B.pdf`…），設好之後
  選手在「作答」分頁按「開啟題目」就會用系統預設的 PDF 閱讀器打開
- **個別指定**：檔名不照慣例時，雙擊清單裡那一列選檔案（相對路徑會
  當作相對於題目資料夾）
- **編譯器**：留空 = 自動偵測；機房的 g++ 裝在特殊位置時可以手動指定

清單會用顏色標出每題的題目檔有沒有找到，綠色代表可用、紅色代表未設定。

設定存在 `config.json`，監考在一台機器上設好之後可以直接複製到其他機器，
或把 `ITOUOJ_HOME` 指到共用資料夾，省去逐台設定。

### 1c. PIN 鎖（選用）

管理員設定裡可以「設定 PIN 並鎖定」。鎖定後**只有**「比賽選擇」和「管理員設定」
會被停用，需要輸入 PIN 才能改。

**登入區塊永遠可用**，不會被鎖 —— 選手的 session 有效期是 7 天，過期後必須
重新登入才能上傳，把登入一起鎖住等於讓他交不出東西。

解鎖只在該次執行有效，關掉程式重開又是鎖著的，監考不會因為忘記重新鎖而讓
整場比賽都開著。

> 這是**防呆，不是防駭**：擋的是比賽中手滑把比賽切掉、或好奇亂改題目路徑。
> PIN 的雜湊存在本機 `config.json`，有檔案存取權的人刪掉就解開了。
> 真正的權限邊界在伺服器（報名檢查、語言限制、時間夾制），客戶端動不了。

登入成功後程式會把 session、題目對應表（PDF 上的 A/B/C → 伺服器的 problemId）
和**時鐘校正值**存到本機。做完這一步就可以斷網了。

> 選手必須事先報名該比賽，否則清單裡會標示「※尚未報名」，上傳時會被拒絕。

### 1d. 登出

「賽前設定」→「帳號」區塊有「登出」。同一台機器要換人用的時候一定要按，
因為登出時會順便**清掉所有草稿** —— 草稿是按「比賽＋題號」存的、不綁使用者，
不清的話下一位選手打開「作答」分頁會直接看到前一位寫的程式碼。

還沒上傳的提交**不會**被刪掉，只是被標上原本的帳號收起來。原本那位選手
之後登回來就能把它們補傳上去；換成別人登入的話，上傳時會跳出提醒並
自動跳過不屬於他的那幾筆，不會誤送到別人帳號底下。

### 1e. 關掉程式會自動回到初始狀態

正常關閉程式時會自動做一次登出（清掉帳號、比賽選擇、草稿），
下一位開起來就是全新的畫面，不必記得手動按登出。

**但有兩種情況不會清**，因為清了會害人交不出東西：

| 情況 | 為什麼不清 |
|---|---|
| 已選比賽且比賽還沒結束 | 機房這時是斷網的，而重新登入需要網路。清掉等於那台機器再也回不來 |
| 還有沒上傳的提交 | 清掉身分後那些提交會變成「別人的」，要原本那位重新登入才傳得出去 |

管理員設定（題目 PDF 路徑、編譯器路徑、PIN、伺服器網址）和時鐘校正值
**一律保留** —— 那些屬於這台機器而不屬於某個人，每換一位就要重設一次太蠢。

判斷邏輯是 `Flow.ShouldResetOnExit`，四個分支都有測試釘住。

### 1f. 狀態列的時鐘

視窗右下角一直顯示這台機器**校正後的現在時間**，任何階段都看得到
（等待／結束的全屏遮罩也蓋不到狀態列）。

「統一開始」整套機制就是靠每台機器對過同一個伺服器時鐘，但在這之前那個
校正值只存在 `config.json` 裡，監考沒辦法確認各機是否真的一致。擺出來之後
巡一遍場就能核對 —— **全場每一台都應該顯示同一個時間**。

還沒登入過（沒有校正值）時會顯示成 `14:00:09 未校正` 並轉成灰色，
免得監考誤以為看到的是校正過的時間。

### 1g. 更新比賽資訊

「賽前設定」→「比賽」旁邊的「更新比賽資訊」。

監考臨時延長比賽、加題、改語言限制之後，選手機上的快取就過期了 ——
而起訖時間正是斷網後判斷開始與結束的唯一依據。按這個會用同一個 session
重新抓一次，不必登出重登（登出會連草稿一起清掉，代價太大）。

按完會直接說有沒有變、變了什麼；比賽被延長的話畫面也會立刻從
「比賽已結束」跳回作答中。

**這顆按鈕不受 PIN 鎖影響** —— 它改不壞任何東西，而比賽被延長時
正是鎖著的狀態下最需要它。

設定完成後，程式會自動向伺服器**回報「這台機器已就緒」**（含電腦名稱）。
監考可以在網站的 `/admin/contests/<id>/status` 一眼看出哪幾台還沒設定好 ——
漏掉一台，那位選手整場都交不出東西，而且要到賽後上傳時才會發現。

「作答」分頁最上方有一條身分列，三種狀態一眼分得出來：

| 顏色 | 意思 |
|---|---|
| 🔴 紅 | 尚未登入，無法提交 |
| 🟠 橘 | 已登入但還沒選比賽 |
| 🟢 綠 | 帳號、比賽都就緒，可以開始 |

### 2. 比賽中（不需要網路）

在「作答」分頁選題目，然後兩種寫法擇一：

- **直接輸入**（預設）：在編輯區直接寫。內容會**每秒自動存成草稿**，
  切換題目、關掉程式、當機都不會丟失，下次打開自動回填。
- **從檔案**：在自己習慣的 IDE 寫完後選檔案上傳。

按「提交」後程式會把程式碼複製一份到本機 spool，並記下當下時間。
可以重複提交同一題，全部都會保留。

> 草稿和提交是兩回事。草稿只是還沒送出的暫存，**只有按下「提交」才算數**。

**測試執行**（提交旁邊那顆按鈕）可以在斷網時先試跑：

- 用選手電腦上的 `g++` 編譯，跑範例測資並自動比對答案
- 也可以切「自訂輸入」自己貼測試資料
- 逾時會自動中止（時限的兩倍再加 1 秒），抓得出無窮迴圈
- 比對規則與伺服器判題**完全一致**（行尾空白、結尾換行、CRLF 都比照處理），
  所以本機顯示「通過」在伺服器上也會過同一筆範例

範例測資是賽前設定時一起下載快取的，**伺服器只會送出 `isSample` 的測資**，
隱藏測資不會離開伺服器。比賽開始前抓的話拿不到範例（避免題目提早外流），
那時測試執行只能用自訂輸入。

編譯器會依序找 `PATH`、Dev-C++、MinGW、MSYS2、TDM-GCC、Code::Blocks 的常見位置。
找不到會跳提示，但**不影響提交與上傳**——只是不能在本機先試跑。

### 3. 賽後（重新連網）

按右下角「上傳到伺服器」。程式會把所有待上傳的提交一次送出，
成功後狀態變成「已上傳」，並在「網站編號」欄顯示伺服器給的提交編號。

重複按不會造成重複提交——每筆提交都有唯一的 `clientKey`，伺服器會自動略過
已存在的（重複時仍會回傳既有編號，所以連結照樣點得到）。
上傳失敗時提交仍保留在本機，可以直接重試。

### 4. 看判題結果

上傳後在「收件紀錄」分頁：

- **雙擊任一列**（或選取後按「查看判題結果」）→ 用瀏覽器開啟該筆的
  `/submissions/<編號>` 詳細頁，看得到 verdict、每筆測資結果和程式碼
- **「計分板」** → 開啟該場比賽的排行榜

編號會寫進本機檔案，關掉程式重開仍然點得到。

## 資料存在哪

預設 `%LOCALAPPDATA%\itouOJ\`：

```
config.json           伺服器網址、session、比賽、題目對應、題目 PDF 路徑、時鐘校正值
pending\<key>.json    待上傳的提交（一筆一個檔）
uploaded\<key>.json   已上傳的提交
drafts\<比賽>-<代號>.cpp  編輯區的自動草稿
build\、run\          測試執行的暫存檔
```

設環境變數 `ITOUOJ_HOME` 可以換位置（例如放到隨身碟，方便監考統一回收）。

一筆提交一個檔是刻意的：寫到一半當掉只會壞掉那一筆，不會整包 manifest 損毀。
選手的程式碼原文都在裡面，真的出狀況時可以手動救回來。

## 幾個設計上的考量

**時鐘校正。** 機房電腦時鐘不準是常態。程式在登入時會從 HTTP 回應的 `Date`
標頭讀出伺服器時間，算出偏移量存起來，比賽中記錄提交時間時套用。沒有這層的話，
時鐘偏掉幾小時的機器交出來的提交會全部被伺服器夾制到比賽邊界，用時就錯了。

**時間戳的信任邊界。** 提交時間是選手機器給的，伺服器會夾制在比賽起訖區間內，
擋掉賽前預先寫好或賽後補交的極端情況；但區間**內**的微調擋不住，這部分要靠監考。
要更嚴謹就得改成監考統一回收 spool。

**支援的副檔名**：`.cpp` `.cc` `.cxx` → C++，`.c` → C，`.py` → Python，
`.java` → Java，`.js` → JavaScript。程式碼上限 64 KB（與伺服器一致）。

**語言限制。** 比賽可以在管理頁的「可用語言」限定語言（例如只開 C++）。
程式會在賽前設定時把限制一起抓下來，之後：

- 檔案對話框只列得出允許的副檔名
- 選到不合規的檔案會當場擋下並說明原因，不會等到賽後上傳才發現
- 提交區右上角會顯示「本比賽限用 C++」

這是選手機上的檢查，擋得住誤操作但擋不住改過的用戶端——所以伺服器端也會擋，
網頁提交、測試執行、離線上傳三條路都一樣。

## 測試

`TestHarness.cs` 會跟 `OfflineSubmit.cs` 一起編譯（用 `/main:` 換掉進入點），
所以測到的是 GUI 實際使用的同一份 `Api` / `Store` 程式碼，不是另外寫的仿冒品。

```powershell
$csc = "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe"
$refs = "System.dll,System.Core.dll,System.Drawing.dll,System.Windows.Forms.dll,System.Web.Extensions.dll"
& $csc /nologo /target:exe /codepage:65001 /main:ItouOJ.TestHarness `
    /out:client\TestHarness.exe "/reference:$refs" client\OfflineSubmit.cs client\TestHarness.cs

$env:ITOUOJ_HOME = "$env:TEMP\itouoj-test"
.\client\TestHarness.exe http://localhost:3000 <帳號> <密碼>
```

會跑完登入、取比賽、取題目、寫 spool、上傳、去重、錯誤處理整條流程。
**不要對正式站跑**，它會真的送出提交。
